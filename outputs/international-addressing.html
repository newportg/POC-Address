Two Standards, Two Purposes

ISO cannot make up its mind — so we compare both

UPU S42 Postal Addressing

Scope: Global postal addressing standard

Focus: Logical structure of postal addresses for mail delivery

Application: Postal operations and cross-border mail

Flexibility: Adaptable by any country

ISO 20022 Financial Messaging

Scope: Financial transaction data format

Focus: Structured data for financial transactions

Application: Banking, payments, regulatory compliance

Coverage: Only 32 countries

Key Differences

Aspect UPU S42 ISO 20022
Type Postal addressing standard Financial messaging standard
Structure Generic elements + country templates Highly structured XML tags
Adaptability Flexible, country-specific Rigid, fixed format
Best For Web applications, mail delivery Financial operations, compliance

✓ Recommendation: UPU S42 is the better choice for most address management scenarios due to its flexibility and wider country coverage.

UPU S42 Addressing Standard

Universal Postal Union framework for postal addressing

The UPU S42 standard provides a comprehensive framework for postal addressing, designed to accommodate the diverse formats used by different countries. It includes a generic list of address elements and country-specific templates to guide users in formatting addresses correctly for mail delivery.

Key Features

  • Universal framework adaptable by any country
  • Generic list of address elements
  • Country-specific templates
  • Promotes efficient mail processing and data verification
  • Designed for easy adaptation by web applications

ISO 20022 Address Schema

Financial messaging standard for transaction data

ISO 20022 defines a standardised, structured data format for financial messaging, including specific, granular fields for address components, primarily for efficiency and accuracy in financial transactions.

⚠ Important: ISO 20022 currently only applies to 32 countries.

ISO 20022 Address Fields

Field XML Tag Description
Department <Dept> Specific business units or departments
Sub Department <SubDept> The sub department name
Street Name <StrtNm> The name of the street
Building Number <BldgNb> The number of the building
Building Name <BldgNm> The name of the building
Floor <Flr> The building floor
Post Box <PstBx> The PostBox
Room <Room> Room number or name
Postal Code <PstCd> The postal code for the address
Town Name <TwnNm> The name of the city or town
Town Location Name <TwnLctnNm> A specific location within a town
District Name <DstrctNm> The name of a larger district
Country Subdivision <CtrySubDvsn> A state, province, or other subdivision
Country <Ctry> Two-character ISO country code
Address Line <AdrLine> Optional additional address information

Evolution

The standard has evolved, with the 2019 version (PostalAddress24) offering a more detailed 15-field structure compared to the 2009 version (PostalAddress6).

Address Formatting

The AddressFormat field from LOQATE defines how to construct the formatted address. It's a string with field names separated by <BR> tags.

Example (UK):

Organisation<BR>DeliveryAddress<BR>Locality AdministrativeArea PostalCode

Rendering Logic:

  1. Split AddressFormat by <BR> to get lines
  2. For each line, split by whitespace to get field names
  3. Look up each field name in the LOQATE response
  4. Join non-empty values with spaces
